**Update:** [The selected Tristram scene is now included through automatic MPQ preparation](/devlog/tristram-completa-mpq-warrior/). Use [the current download](/download/).

## One download with the runtime files

The first local3 ZIP was a technical checkpoint that depended on local private files. We preserved it and published **local3 FULL**, including the executable, libraries, public R17 resources, three own Warrior packets and Clock.

[Download the complete Windows package](/download/). Extract it and run **Iniciar-Diablo3D.cmd**. Select **DIABDAT.MPQ from your original Diablo copy**. The selection is remembered; no Python, compiler, private files or external HD pack is required.

This is a development preview. Warrior Light with Short Sword/Buckler has support in Town and Cathedral 1, with first/third person and HUD R4. K switches cameras, Home restores third person, and F4 switches 3D/native. The whole game in 3D remains unfinished.

## The project is on GitHub

[The repository](https://github.com/douglasopan/diablo-3d) contains the frozen local3 engine, authoring tools, Godot editor, documentation, concepts and own resources. [The development snapshot branch](https://github.com/douglasopan/diablo-3d/tree/snapshot/workspace-20261014) preserves unfinished local changes and does not represent the qualified executable. Large distribution files are release attachments.

## What this publication verified

File hashes, ZIP integrity, Douglas Pan artist tags on own recordings, and fresh profile preparation passed. The executable remains the original local3; no new performance patch was applied. Saves and preferences use a separate `%LOCALAPPDATA%/Diablo3D-local3-full/profile`.

The private cardinal staging scene is excluded. Town uses your original game data. Previous private assembly gates do not automatically qualify this new resource combination: **manual gameplay validation of this public assembly and performance remain pending**. The article image is a historical automated capture from the private local3 assembly.

No MPQ, saves, credentials or proprietary extracts are published. Development continues from the preserved checkpoint and existing queue.
